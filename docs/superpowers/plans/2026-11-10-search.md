# Search across all sessions: implementation plan

**Goal:** fuzzy-find sessions and parts of conversations (titles, prompts, answers, optionally
tool calls) across every Claude Code session, with a prompt-history view. Built once in the
helper, cached on disk, updated incrementally, instant per keystroke. A limited Lua fallback
(titles and prompts, exact matching) keeps it usable without the helper.

## Architecture

```
picker (ui/search.lua, ui/search_view.lua)
  │ live query per keystroke (10 ms debounce, one request in flight, newer query replaces older)
  ▼
index/search.lua  facade: helper when available, else index/search_lua.lua (limited)
  │ `search` / `context` requests, `search_ready` notification
  ▼
helper/src/search/{mod,index,store,query}.rs
  index built in a background thread on first use, persisted to <cache>/search-v1.json,
  refreshed (stat of every transcript, re-index of changed ones, append-only files parsed
  from the last indexed byte) at most once per second when searched
```

Opening a hit: `ui/search_open.lua` ensures the Agents tab, opens the chat (`chat.open`), waits
for the history to load and places the cursor on the event's line. The line is computed from
the renderer (`transcript/locate.lua`): the turn offsets are the rendered line counts of the
turns before (as in `ui/textobj.lua`), and the line inside the turn is found by rendering the
turn's events before the hit with an empty text event appended (the trick `transcript/live.lua`
uses for streaming lines), never by searching buffer text.

## Indexed documents

Per session: title (scan title rule), project name (sent by Lua as a cwd → name map; fallback
the basename of cwd), and one chunk per event:

| kind     | event                                  | text                                  |
|----------|----------------------------------------|---------------------------------------|
| `prompt` | `prompt`, not sidechain, non-blank      | prompt text, first 4 KiB              |
| `answer` | `text`, not sidechain, non-blank        | answer text, first 4 KiB              |
| `tool`   | `tool_call`, not sidechain              | `Name: summary` (first 200 bytes)     |

Each chunk keeps the 1-based index of its event in the list `history` returns, and the record's
timestamp when it has one. Chunk text is capped (4 KiB, cut at a character boundary) so the
index never holds whole transcripts; a longer prompt is still copied in full (`<C-y>`, `<C-r>`)
because the copy reads the event from the transcript. Sidechain (subagent) events are not
indexed. For previews, each session also keeps the byte offset of every line that starts a turn.

## Protocol (helper line protocol; `docs/protocol.md` is about Claude's stream and stays as it is)

`search` params: `{ projects_dir, query, scope, kinds?, limit?, fuzzy?, projects? }`
- `scope`: `"all"` | `{ "project": key, "sessions": [id] }` | `{ "session": id }`
- `kinds`: subset of `title`, `prompt`, `answer`, `tool` (default the first three)
- `limit`: default 50, at most 500; `fuzzy`: default true; `projects`: `{ cwd: name }`

result: `{ hits, indexing, sessions, chunks, took_ms }`, each hit
`{ session, path, cwd, project, title, kind, event|null, ts|null, snippet, positions, match }`,
`positions` = byte ranges `[start, end)` in `snippet`, `match` = `prefix` | `substring` |
`fuzzy` | `recent` (empty query).

`context` params `{ path, event }` → `{ first, events }`: the events of the turn holding the
event, `first` = index of `events[1]`.

Notification `search_ready` `{ sessions, chunks }` after the index changed.

## Matching and ranking

Words are split on whitespace and all must match the same chunk, in any order. Per word, best of:
`prefix` (case-insensitive substring at a word start), `substring`, `fuzzy` (`neo_frizbee`
Smith-Waterman per line of the chunk, typos allowed for longer words, minimum score). Smart case:
a word with an uppercase letter matches case-sensitively. Non-ASCII words compare characters
lower-cased (umlauts). The chunk's match is its weakest word. Order: exact (prefix or substring)
before fuzzy; then title > prompt > answer > tool; then prefix before substring, fuzzy by score;
then newest first. Empty query: newest first (prompt history when kinds = prompt).

## Tasks (each test first)

1. **Helper index** (`index.rs`, `store.rs`): build from a projects dir, incremental append,
   rewrite and delete, versioned cache file. Tests: chunk event indexes equal `parse_bytes`
   positions; caps; sidechain skipped; append keeps indexes; shrink re-indexes; deleted file
   dropped; other-version cache ignored; save/load round trip.
2. **Helper query** (`query.rs`, `snippet.rs`): tests for prefix/substring/fuzzy order, kind
   order, recency tie-break, multi-word any order, smart case, umlauts, spaces-only and special
   characters, empty query newest first, scope, `tool` only on request, snippet positions on
   char boundaries for long lines.
3. **Helper protocol** (`mod.rs`, `protocol.rs`): background build, `search`, `context`,
   `search_ready`. Tests through `Server::handle_line`; budget test in release builds (200
   sessions / 50 MB < 3 s build, query < 30 ms).
4. **Lua facade and fallback** (`index/search.lua`, `index/search_lua.lua`, `search/match.lua`):
   tests: fallback hits on fixtures, same hit shape, never blocks (gap probe), parity with the
   helper (same sessions for exact substring queries on titles and prompts, fixtures and
   generated data, umlauts included).
5. **Locate** (`transcript/locate.lua`): event → line from the renderer; tests against full
   renders of fixtures and synthetic turns (results after text, parallel calls).
6. **Picker** (`ui/search.lua`, `ui/search_view.lua`): child-Neovim tests for typing, moving,
   preview, scope cycling, kinds, stale responses dropped, close keys, title/backend label.
7. **Open, copy, reuse, entry points** (`ui/search_open.lua`, init/config/drawer/plugin): tests
   for `<CR>` cursor line and fold, missing transcript, `<C-y>`, `<C-r>`, `:AgentsSearch`, keys,
   drawer `s` scoped to the project, help row, `/` untouched.
8. **Budgets** (`tests/test_search_budget.lua`): helper build < 3 s and query < 30 ms on 200
   synthetic sessions (about 50 MB), keystroke to results < 60 ms end to end, no UI block.
9. Review, docs, real-data smoke check (numbers only).
