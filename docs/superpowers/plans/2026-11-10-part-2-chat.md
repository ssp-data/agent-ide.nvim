# Agent-IDE.nvim Part 2: Chat — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prompt Claude Code from a normal Neovim buffer and read its streamed answer as rendered markdown with tool calls as folds, with Claude's own permissions, model and mode switching, a status footer, and no interruption of typing.

**Architecture:** One long-lived `claude -p` process per open session speaks line-delimited JSON over stdin/stdout. A pure decoder turns stream objects into actions; a Session object holds state and the shared Event list of part 1; the transcript buffer is updated incrementally and always equals what `render.render` gives for the same events. UI sits in the Agents tab: transcript in the main window, prompt buffer below.

**Tech Stack:** Lua (Neovim 0.12, `vim.system`, `vim.uv`), mini.test, the part 1 modules (`transcript/parse`, `transcript/render`, `index`, `live`, `ui/*`), Rust helper (one small change in Task 1).

**Spec:** `docs/superpowers/specs/2026-11-10-agents-ide-design.md` (sections 4, 5.1, 6, 7.2, 7.3, 7.4, 7.7, 7.8, 8, 9, 12). Part 1 plan: `docs/superpowers/plans/2026-11-10-part-1-drawer-and-history.md` (Shared Types).

## Global Constraints

- All part 1 constraints still hold: module `agent-ide`, highlight prefix `AgentIde`, Neovim 0.12+, no runtime Lua dependencies, synthetic fixtures only, nothing from `~/.claude` in the repo, never change the global working directory, never stop a Claude process the plugin did not start, no synchronous subprocess wait or file scan on the UI thread, Lua and Rust backends give identical results.
- **Subscription only (spec 5.1):** every Claude process the plugin starts has `ANTHROPIC_API_KEY` removed from its environment unless `claude.strip_api_key = false`.
- **Command line (spec 6), exact:** `claude -p --verbose --input-format stream-json --output-format stream-json --include-partial-messages --replay-user-messages --permission-prompts host --permission-prompt-tool stdio` plus `--session-id <uuid>` for a new session or `--resume <id>` for an existing one. The executable and leading arguments come from `config.claude.cmd` (default `{ 'claude' }`) so tests can use a fake.
- **Fidelity (spec 8):** every stream object is rendered or shown as a labelled fold; prompts are sent verbatim except `[attach] <path>` lines becoming `@<path>`; after a turn the buffer equals `render.render(events).lines` for that session's events.
- **Never interrupt (spec 7.8):** no popup, focus change or cursor move in a window the user is typing in, caused by a session that is not the one shown in the focused chat view.
- **Speed (spec 9.1):** typing in the prompt buffer is never blocked; a text delta reaches the buffer in the same event-loop tick it is decoded; sending does not start a process when one is alive.
- Real Claude is used only in Task 11, on the `haiku` model, in a temporary git repo. All other tests use a fake Claude script.
- Tested Claude Code version: `2.1.306`.
- Commits end with `Co-Authored-By: Claude <noreply@anthropic.com>`. Branch `full-build`. `README.md` has a staged edit by the user: never include it in a commit unless a task changes README, and then keep the user's edit.

## Review Focus

1. **Answer text containing fold-like or header-like lines** (`▸ `, `│`, `## You`) streams and re-renders as plain text; folds and turn boundaries come from events only. → Task 5.
2. **Claude process dies mid-answer** (crash, `kill`, quota error): partial text stays, an `error` line is appended, state returns to idle, next send resumes with `--resume`. → Task 4.
3. **Two sends in a row / send while busy:** the second prompt is queued and sent after the current turn, shown in the transcript in order; nothing is lost. → Task 4, Task 6.
4. **Permission ask from a session not on screen** while the user types in another buffer: no popup; drawer and footer show waiting; answering later still works and the tool runs. → Task 8.
5. **Prompt with trailing blank lines, tabs, CRLF, code fences, a line that only looks like `[attach]` inside a fence:** sent byte-exact except real `[attach]` lines outside code fences. → Task 7.

## Shared Types (additions)

**SessionMeta** gains `activity` (integer seconds): time of the last `user`/`assistant` record found in the last 256 KiB, else in the first 256 KiB, else `mtime`. The drawer shows ages and sorts by `activity`.

**Action** (from `stream.decode`):

| type | fields |
|---|---|
| `init` | `session_id`, `model`, `mode`, `slash_commands` (string[]), `version` |
| `status` | `mode` (optional), `busy` (boolean, optional) |
| `delta` | `text` |
| `event` | `event` (part 1 Event) |
| `echo` | `text` (replayed user prompt) |
| `permission` | `request_id`, `tool_name`, `input`, `description`, `suggestions` |
| `control_ok` / `control_error` | `request_id`, `response` / `error` |
| `quota` | `windows` (table: name → `{ utilization, resets_at }`) |
| `result` | `is_error`, `text` |
| `unknown` | `label`, `raw` |

**Session state:** `'parked' | 'idle' | 'busy' | 'waiting' | 'done' | 'failed'`. `waiting` = a permission ask or question is open. `done` / `failed` = last turn ended while the session was not on screen (result unread); viewing the session turns them into `idle`.

**Status level** (spec 7.8): 4 violet when any session is `waiting`; else 3 orange when any is `done` or `failed`; else 2 yellow when any is `busy`; else 1 green.

### Task 4: Session model and registry

**Files:**
- Create: `lua/agent-ide/session.lua`
- Test: `tests/test_session.lua`

**Interfaces:**
- Consumes: `process`, `stream`, `index.history`, part 1 Event.
- Produces:
  - `session.open(opts: { id?: string, cwd: string, path?: string, title?: string }) -> Session` (same object for the same id; a new id is a fresh UUID v4), `session.get(id)`, `session.all() -> Session[]`, `session.on_change(fn(session, what))` where `what` ∈ `'state' | 'events' | 'delta' | 'meta' | 'permission' | 'quota'`.
  - Session fields: `id`, `cwd`, `path`, `title`, `state`, `model`, `mode`, `slash_commands`, `events` (Event[]), `streaming` (string, text of the answer in progress), `turn_start` (index into `events` of the current turn's prompt), `pending_permissions` (list), `queue` (prompts waiting), `raw` (list of raw lines, capped at 5000), `unread` (boolean), `owned` (boolean: this Neovim runs its process).
  - Methods: `s:load(cb)` (history via `index.history` when `path` exists; idempotent; reloads when the file's mtime/size changed and no process is alive), `s:send(text) -> boolean, reason?`, `s:interrupt()`, `s:set_mode(mode)`, `s:set_model(model)`, `s:answer(request_id, allow: boolean, opts?)`, `s:park(cb?)`, `s:mark_seen()`.
- Rules:
  - `send` starts the process when none is alive (`resume` = the session has a transcript or has sent before), appends a `prompt` event, sends the user JSON line, state `busy`. While `busy` or `waiting`, `send` queues; queued prompts are appended as events and sent in order when their turn starts.
  - `send` returns `false, 'running elsewhere'` when `live.get()` lists this session id and `owned` is false.
  - `delta` appends to `streaming`; a `text` event for the same message clears `streaming`.
  - `permission` action: pushed to `pending_permissions`, state `waiting`; `answer` sends the control response (`{ behavior = 'allow', updatedInput = input }` or `{ behavior = 'deny', message = 'Denied by user in Neovim' }`), pops it, state back to `busy` when none remain.
  - `result`: state `idle` if the session is marked on screen (`s.visible`, set by the chat view), else `done` (or `failed` when `is_error`) and `unread = true`; `mark_seen` turns `done`/`failed` into `idle`. An `is_error` result appends `{ kind = 'meta', label = 'error', text = <text> }`.
  - Process exit while `busy`/`waiting`: `streaming` text is kept as a `text` event, a `meta` event with label `error` and text `Claude exited (code <n>)` plus the stderr tail is appended, pending permissions are cleared, state `failed`/`idle` by the same visibility rule, queue kept.
  - `echo` action: compared with the prompt sent; a difference appends a `meta` event label `warning`, text `Prompt echoed by Claude differs from what was sent` and notifies once per session at WARN.
  - `init`/`status` update `model`, `mode`, `slash_commands`; `quota` is forwarded.
  - `park`: refuses with a confirm when `busy` (callback gets `false` if declined); stops the process; state `parked`.
