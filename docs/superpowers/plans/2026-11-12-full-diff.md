# Full Diff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only buffer in the Agents tab's main window that shows the whole diff of a scope (branch, commits, one commit, uncommitted) file by file with folds, opened from the drawer (`gd`, two `full diff` rows), the graph (`gd`) and `:AgentsDiff`; `<CR>` jumps into the side-by-side view and `q` comes back.

**Architecture:** Pure parsing (`git_parse.patch`) and pure rendering (`ui/fulldiff_render.lua`) are tested without a window and hold a speed budget. `git_patch.lua` runs the read-only git queries per scope and joins the patch with the scope's file list from `git_cache`. `ui/fulldiff.lua` owns the buffer, the window options, the manual folds and the reload on cache invalidation, modelled on `ui/graph.lua`; `ui/fulldiff_keys.lua` maps `keys.full_diff` like `graph_keys.lua`; `ui/fulldiff_open.lua` turns a drawer row into a scope.

**Tech Stack:** Neovim 0.12 Lua, `vim.system` through `git.run`, extmarks, manual folds, mini.test (`make test`, `TEST_FILE=… make test`).

**Spec:** `docs/superpowers/specs/2026-11-12-full-diff-design.md`

## Global Constraints

- AGENTS.md rules apply: git is read-only through `git.run` (`--no-optional-locks`); nothing synchronous on the UI thread; no dependencies; privacy (synthetic fixtures, temporary folders); files near 350 lines.
- Every configurable key goes through `util/keys.lua`, accepts a key, a list, or `false`, and is listed in the view's help and the README key tables.
- Highlight groups: `default = true`, re-applied on `ColorScheme`; dimmed text never italic.
- Name in every user-facing string: "full diff". Buffer name `agents://<project>/full diff`, filetype `agent-ide-fulldiff`.
- Context: three lines (`-U3`). Files whose block is longer than 500 lines start folded closed.
- Untracked files read with the limits of `git.lua`'s `count_lines`: 2 MiB per file, 16 MiB in total, 4 at a time.
- Budget: 50 000 patch lines (500 files) parsed, rendered into a buffer with highlights and folds, best of 5, under 60 ms.
- Work on branch `dev`; commit only the files of each task (the working tree holds unrelated uncommitted work: never `git add -A`).
- `CHANGELOG.md`, README and AGENTS.md updated in the same change (Task 7).

## Review Focus

1. Paths with spaces, quotes, backslashes or non-ASCII bytes: git C-quotes them in `diff --git` lines; the block must still join its file-list entry (exact path from `-z`). Test in Task 1 (`parse.unquote`, quoted header) and Task 3 (a file named `sp ace "q".txt` in the repository).
2. A file that changed between the file list and the patch (or a `diff --cc` conflict block, `@@@` hunks): a block without a list entry is shown under a header built from the block, never dropped. Test in Task 2.
3. `\ No newline at end of file` and CRLF lines: shown as git prints them, dimmed like a hunk header, not counted as a new-side line. Test in Task 2 (`nodes` offsets skip it).
4. An untracked file over 2 MiB or with a NUL byte: a note under its header, Neovim never reads it fully. Test in Task 3.
5. A repository without commits, an empty scope, a missing folder: one dimmed line or a notice, no error. Test in Task 3 (empty repository) and Task 4 (empty scope line).

### Task 1: Patch parser (pure)

**Interfaces:**
- Produces: `parse.unquote(s: string): string` (C-style unquoting of a git-quoted path: `\"`, `\\`, `\t`, `\n`, `\r`, `\ooo` octal; a string without surrounding quotes returns unchanged).

### Task 2: Renderer (pure) and its budget

**Files:**
- Create: `lua/agent-ide/ui/fulldiff_render.lua`
- Modify: `lua/agent-ide/ui/highlights.lua` (two groups)
- Test: `tests/test_fulldiff.lua` (section "render"), `tests/test_fulldiff_budget.lua` (new)

**Interfaces:**
- Consumes: `parse.patch` blocks (Task 1); `git_sections.STATUS_HL`, `git_sections.stats(f)`; `layout.row(left, right, width)`.
- Produces: `render.build(files: table[], blocks: table<string, table>, opts): table` where `files` is a scope's file list (`{ status, path, old_path?, added?, removed?, binary, submodule, dir?, untracked? }`, as `git_cache` holds it), `blocks` maps a path to its block (`{ lines, binary?, mode_only?, note? }`; a generated untracked block has `lines`; a block with `note` shows that string), and `opts = { icons = { open, closed }, width: integer, closed: table<string, boolean>|nil, fold_over: integer (500) }`. Returns `{ lines: string[], hl: { line, col_start, col_end, group }[], folds: { first, last, closed: boolean, path }[], files: { path, line }[], nodes: table }`, where `nodes[i]` for a line of a hunk is `{ file: integer, new_line: integer|nil }` (`new_line`: the new-side line number of a context or `+` line; nil on `@@`, `-`, `\` lines) and for a header `{ file = k, header = true }`.
- Highlight groups: `AgentIdeDiffHunk` (dim, the `@@` and `\` lines) and `AgentIdeDiffNote` (dim, the notes), added to `highlights.lua`'s table next to `AgentIdeDiffAdd`.

Rendering rules (the spec's "What the user sees"): header `= icon .. ' ' .. status .. ' ' .. name` left, `git_sections.stats(f)` right through `layout.row(..., opts.width)`; a blank line after each file's last line; the fold of a file runs from its header to that blank line; `closed` = `opts.closed[path]` when the key is present, else `#block.lines > fold_over`. Blocks without a list entry are appended after the listed files with status `M` and the block's path (Review Focus 2). Notes: `binary file, not shown` (list `binary` or block `binary`), `submodule: not shown`, `mode changed` (`mode_only`), `block.note` verbatim; a file with neither block nor note gets `no changes shown` (dim). Empty `files` gives `lines = {}` (the view puts its own one-liner).

**Interfaces:**
- Consumes: `git.run`, `git.base`, `cache.when(root, kind, cb)`, `cache.changes/commits/commit_files/uncommitted`, `parse.patch`, `parse.paths`.
- Produces in `git_patch.lua`:
  - `M.committed(root, base, cb(files))`: the file list between the commits scope's start and `HEAD` with the drawer's `--raw --numstat -z -M` flags (`parse.raw_numstat`); start = `base.merge_base` in branch mode; in recent mode `M.start(root, base, cb(rev))` resolves it from `cache.when(root, 'commits')`: `<oldest listed>^`, verified with `rev-parse -q --verify`, else the empty tree (`hash-object -t tree /dev/null`); without commits, `cb(nil)` and `committed` gives `{}`.
  - `M.load(root, scope, cb(res))` with `scope = { kind: 'branch'|'commits'|'commit'|'head', commit?: { hash, short, subject, date } }` and `res = { files: table[], blocks: table<string, table>, label: string, error?: string }`. `label` per spec: `vs <base.label>`, `commits on branch` / `recent commits`, `<short> <subject>`, `uncommitted`. Commands (all with `-c core.quotePath=false` before the subcommand and `--no-color --no-ext-diff --no-textconv -M -U3`): branch `diff <base.rev> --`, commits `diff <start> HEAD --`, commit `diff-tree -p -r --root --no-commit-id --diff-merges=first-parent <hash> --`, head `diff HEAD --`. Files from the matching cache kind (`changes`, `committed`, `files:<hash>`, `uncommitted`) through `cache.when`. Untracked files (`f.untracked`, not `f.dir`) read with `vim.uv` under `git.read_limits`: a block `{ lines = { '@@ -0,0 +1,N @@', '+…' } }` (an empty file: `{ lines = {} }`), a NUL byte: `{ binary = true }`, over the limits: `{ note = 'not shown (larger than 2 MiB)' }`. Failures: a non-zero git exit gives `res.error` = first line of stderr.
- In `git_cache.lua`: loader `committed` (through `with_base`, then `git_patch.committed`), getter `M.committed(root)`, and `committed` in `getters` so `cache.when(root, 'committed', cb)` works; invalidation covers it like `changes`.
